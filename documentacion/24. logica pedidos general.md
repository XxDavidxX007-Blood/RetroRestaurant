# 🧾 Pedidos — Vista General del Módulo

## ¿Qué es?

El módulo de pedidos conecta al cliente con la cocina. El cliente hace un pedido desde el catálogo, el admin lo ve en su panel y cambia su estado conforme avanza. El cliente puede ver, editar y cancelar sus pedidos pendientes.

---

## Archivos que participan

```
views/dashboard/cliente_catalogo.php      →  el cliente elige platos y confirma el pedido
Controllers/ProcesarCompra.php            →  endpoint AJAX que recibe el carrito
Controllers/CompraController.php          →  crea el pedido, detalles, factura y notificaciones en la BD
Controllers/PedidoController.php          →  lógica del panel admin (filtros, KPIs, cambio de estado)
Controllers/PedidoDetalleCliente.php      →  endpoint AJAX para ver/editar detalles desde el cliente
models/Pedido.php                         →  todas las consultas SQL de pedidos
views/dashboard/admin_pedidos.php         →  panel admin: tabla, filtros, KPIs, modales
views/dashboard/admin_pedidos_detalle.php →  fragmento HTML del detalle (cargado por AJAX)
views/dashboard/cliente_pedidos.php       →  panel cliente: historial, editar, cancelar, eliminar
```

---

## Tablas de la BD involucradas

| Tabla | Para qué |
|---|---|
| `pedido` | Registro principal del pedido |
| `detalle_pedido` | Productos dentro del pedido (uno por fila) |
| `factura` | Total del pedido y método de pago |
| `estado_pedido` | Catálogo de estados (pendiente, en_preparacion, listo, entregado, cancelado) |
| `tipo_pedido` | Catálogo de tipos (mesa, domicilio, para llevar) |
| `cliente` | Quién hizo el pedido |
| `mesero` | Quién atiende el pedido (se asigna automáticamente) |
| `notificacion` | Alertas generadas al crear el pedido |

---

## Los 5 estados de un pedido

```
pendiente → en_preparacion → listo → entregado
                                   ↘ cancelado
```

| Estado | Color | Quién lo cambia |
|---|---|---|
| pendiente | Amarillo | Inicial al crear |
| en_preparacion | Azul | Admin/empleado |
| listo | Verde | Admin/empleado |
| entregado | Morado | Admin/empleado |
| cancelado | Rojo | Admin/empleado o cliente (solo si está pendiente) |

---

## Flujo completo de un pedido

```
1. Cliente abre el catálogo → elige un plato → abre el modal de confirmación
2. Selecciona cantidad, tipo (mesa/domicilio/llevar) y confirma
3. JS hace POST a ProcesarCompra.php con el carrito en JSON
4. ProcesarCompra.php llama a CompraController::procesarCompra()
5. CompraController crea en la BD (transacción):
   → INSERT pedido (estado=pendiente)
   → INSERT detalle_pedido (uno por producto)
   → INSERT factura (total calculado)
   → INSERT notificacion (al admin y al cliente)
6. Responde JSON {ok:true, id_pedido, total}
7. El cliente ve el modal de éxito con el número de pedido
8. Admin ve el pedido en admin_pedidos.php
9. Admin cambia el estado conforme avanza
10. Cliente puede ver el estado en cliente_pedidos.php
```
