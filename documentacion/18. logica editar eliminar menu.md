# ✏️ Editar y Eliminar Plato — Gestión de Menú

## ¿Qué hacen?

- **Editar** — modifica los datos de un plato ya existente, incluyendo la opción de cambiar su imagen o su visibilidad
- **Eliminar** — borra el plato del menú permanentemente

Ambas opciones aparecen en el dropdown `⋮` de cada fila, igual que en inventario.

---

## Los archivos que participan

```
views/dashboard/admin_gestion_de_menu.php   →  dropdown + modales + JS
Controllers/MenuController.php              →  procesa el POST de editar/eliminar
models/Menu.php                             →  ejecuta UPDATE y DELETE en la BD
```

---

## El dropdown de acciones

Mismo patrón que inventario — un botón `⋮` por fila que abre un menú flotante:

```php
// Botón por fila:
<button onclick="toggleDropdown(<?= $item['id_producto'] ?>)">
    <i class="fas fa-ellipsis-v"></i>
</button>

// Dropdown (oculto por defecto):
<div id="dropdown-<?= $item['id_producto'] ?>" class="hidden ...">
    <a onclick="abrirModalEditar(<?= json_encode($item) ?>)">Editar Plato</a>
    <a onclick="abrirModalEliminar(<?= $item['id_producto'] ?>)">Eliminar del Menú</a>
</div>
```

```js
function toggleDropdown(id) {
    // Cierra todos los otros dropdowns
    document.querySelectorAll('[id^="dropdown-"]').forEach(el => {
        if (el.id !== 'dropdown-' + id) el.classList.add('hidden');
    });
    document.getElementById('dropdown-' + id).classList.toggle('hidden');
}

// Clic fuera → cierra todos
window.onclick = function(e) {
    if (!e.target.closest('.dropdown-container')) {
        document.querySelectorAll('[id^="dropdown-"]').forEach(el => el.classList.add('hidden'));
    }
}
```

## EDITAR

### ¿Cómo se pre-llena el modal?

PHP pasa todos los datos del plato como JSON en el `onclick`. JS los toma y llena el modal sin petición al servidor:

```js
function abrirModalEditar(item) {
    document.getElementById('edit_id_producto').value    = item.id_producto;
    document.getElementById('edit_nombre').value         = item.nombre;
    document.getElementById('edit_precio').value         = item.precio;
    document.getElementById('edit_descripcion').value    = item.descripcion || '';
    document.getElementById('edit_disponible').checked   = item.disponible == 1;

    // Categoría: busca por value (id) o por texto (nombre)
    let catSelect = document.getElementById('edit_categoria');
    for (let i = 0; i < catSelect.options.length; i++) {
        if (catSelect.options[i].value == item.id_categoria ||
            catSelect.options[i].text  === item.categoria) {
            catSelect.selectedIndex = i; break;
        }
    }

    // Imagen actual: si tiene ruta de archivo, la muestra; si no, muestra emoji
    const previewImg = document.getElementById('edit_preview_img');
    const img = item.imagen || '';
    if (img && (img.includes('/') || img.includes('.'))) {
        previewImg.src = '../../img/menu/' + img;
    } else {
        previewImg.parentElement.innerHTML = '<span class="text-3xl">' + (img || '🍽️') + '</span>';
    }

    openModal('modalEditarProducto');
}
```

### Campos editables

| Campo | Editable |
|---|---|
| Nombre | Sí |
| Categoría | Sí |
| Precio | Sí |
| Descripción | Sí |
| Imagen | Sí — subir nueva o dejar vacío para mantener la actual |
| Disponible (visible) | Sí — checkbox |

### La imagen al editar — comportamiento especial

```php
// En el controlador:
$imgNombre = $this->subirImagen(); // null si no se subió nada

$datos = [
    ...
    'imagen' => $imgNombre,  // null = no cambiar la imagen actual
];
```

```php
// En el modelo, si imagen es null → no toca la columna imagen:
if ($datos['imagen'] === null) {
    UPDATE producto SET nombre=:nombre, precio=:precio, ... 
    WHERE id_producto=:id AND es_menu=1
    // imagen NO está en el SET
} else {
    UPDATE producto SET nombre=:nombre, precio=:precio, imagen=:imagen, ...
    WHERE id_producto=:id AND es_menu=1
    // imagen SÍ se actualiza
}
```

Esto evita borrar la imagen existente si el admin no sube una nueva.

### ¿Qué pasa en la BD?

```sql
-- Solo actualiza producto (no toca inventario):
UPDATE producto
SET id_categoria=:id_categoria, nombre=:nombre, precio=:precio,
    descripcion=:descripcion, disponible=:disponible [, imagen=:imagen]
WHERE id_producto=:id AND es_menu=1
```

El `AND es_menu = 1` es una protección extra — evita editar accidentalmente un insumo de inventario.

## ELIMINAR

### ¿Cómo funciona el modal de confirmación?

Al hacer clic en "Eliminar del Menú", se abre un modal de advertencia. Solo guarda el ID:

```js
function abrirModalEliminar(id) {
    document.getElementById('delete_id_producto').value = id;
    openModal('modalEliminarProducto');
}
```

El modal tiene dos botones: **Cancelar** (cierra el modal) y **Sí, eliminar plato** (envía el formulario).

### ¿Qué pasa en la BD?

```php
// El modelo borra en orden por las foreign keys:
BEGIN TRANSACTION
  DELETE FROM inventario WHERE id_producto = :id   // primero el registro dummy
  DELETE FROM producto   WHERE id_producto = :id AND es_menu = 1  // luego el plato
COMMIT
```

El `AND es_menu = 1` protege de borrar insumos de inventario por error.

---

## Flujo comparado

```
EDITAR:
clic ⋮ → dropdown → clic "Editar Plato" → modal pre-llenado
→ admin modifica (imagen opcional) → POST accion=editar
→ UPDATE producto (con o sin imagen)
→ redirect ?success=editado

ELIMINAR:
clic ⋮ → dropdown → clic "Eliminar del Menú" → modal de confirmación
→ admin confirma → POST accion=eliminar
→ DELETE inventario + DELETE producto (es_menu=1)
→ redirect ?success=eliminado
```

---

## Cosas a tener en cuenta

- **La eliminación es permanente** — no hay papelera. El modal de confirmación es la única protección.
- **La imagen anterior no se borra del servidor** al editar — si se sube una nueva, la vieja queda en `img/menu/` sin usarse. No hay limpieza automática de archivos huérfanos.
- **El checkbox `disponible`** es la forma de "ocultar" un plato sin borrarlo — útil cuando un plato se agota temporalmente.
- **La categoría se busca por ID primero**, y si no coincide, por nombre. Más robusto que inventario que solo busca por nombre.
