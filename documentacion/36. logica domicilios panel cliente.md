# 👤 Mis Domicilios — Panel del Cliente

## ¿Qué hace?

El cliente ve únicamente sus pedidos a domicilio en modo lectura. No puede crear, editar ni cancelar desde aquí — esas acciones se hacen desde el catálogo y el módulo "Mis Pedidos".

---

## Archivos involucrados

```
views/dashboard/cliente_domicilios.php   →  vista completa (sin controlador, sin modelo)
```

No usa `DomicilioController` ni `Domicilio.php` — hace las queries directamente en la vista.

---

## Cómo obtiene los pedidos

```php
// 1. Obtiene el id_cliente desde la sesión
$stmtCli = $db->prepare("SELECT id_cliente FROM cliente WHERE id_usuario = :id LIMIT 1");
$stmtCli->execute([':id' => $usuario['id_usuario']]);
$id_cliente = $clienteRow['id_cliente'] ?? null;

// 2. Query principal con filtro de tipo y estado opcional
SELECT p.id_pedido, p.fecha_pedido,
       ep.nombre_estado AS estado,
       IFNULL(f.total_factura, 0) AS total,
       COUNT(dp.id_detalle) AS num_productos
FROM pedido p
JOIN tipo_pedido   tp ON p.id_tipo_pedido   = tp.id_tipo_pedido
JOIN estado_pedido ep ON p.id_estado_pedido = ep.id_estado_pedido
LEFT JOIN factura  f  ON f.id_pedido        = p.id_pedido
LEFT JOIN detalle_pedido dp ON dp.id_pedido = p.id_pedido
WHERE p.id_cliente = :id_cliente
  AND (tp.nombre_tipo LIKE '%domicilio%' OR tp.nombre_tipo LIKE '%delivery%')
  [AND ep.nombre_estado = :estado]  -- si hay filtro activo
GROUP BY p.id_pedido
ORDER BY p.id_pedido DESC
```

El `COUNT(dp.id_detalle)` con `GROUP BY` cuenta cuántos productos tiene cada pedido para mostrarlo en la tarjeta.

## Los tabs de filtro

Solo 4 opciones (menos que el admin):

```
Todos | En camino | Entregado | Cancelado
```

Nota: el tab "En camino" filtra por estado `listo` (no por "en_camino"):
```php
$tabs = [
    'todos'     => 'Todos',
    'listo'     => 'En camino',    // estado BD = 'listo'
    'entregado' => 'Entregado',
    'cancelado' => 'Cancelado',
];
```

No hay filtro de fecha ni paginación — muestra todos los domicilios del cliente de una vez.

## Cómo se muestra cada pedido

Cada pedido es una fila horizontal con 4 secciones:

```
[Ícono estado] | [Número + fecha + productos] | [Badge estado + descripción] | [Total]
```

La función `badgeDomicilio()` devuelve colores, ícono Font Awesome y una descripción amigable:

```php
function badgeDomicilio($estado) {
    $map = [
        'pendiente'      => [..., 'icon'=>'fa-hourglass-half', 'desc'=>'Esperando confirmación'],
        'en_preparacion' => [..., 'icon'=>'fa-fire-burner',    'desc'=>'Estamos preparando tu pedido'],
        'listo'          => [..., 'icon'=>'fa-motorcycle',     'desc'=>'Tu pedido va en camino'],
        'entregado'      => [..., 'icon'=>'fa-check-circle',   'desc'=>'Pedido entregado'],
        'cancelado'      => [..., 'icon'=>'fa-ban',            'desc'=>'Pedido cancelado'],
    ];
}
```

El estado `listo` muestra el ícono de moto y el texto "Tu pedido va en camino" — más descriptivo que el nombre técnico del estado.

## Estado vacío

Si el cliente no tiene domicilios, se muestra un estado vacío con un botón que lleva al catálogo:

```html
<a href="cliente_catalogo.php">Ver catálogo</a>
```

---

## Cosas a tener en cuenta

- **Solo lectura** — el cliente no puede hacer ninguna acción desde aquí. Para cancelar o editar un pedido a domicilio debe ir a "Mis Pedidos".
- **Sin paginación** — si el cliente tiene muchos domicilios, todos se cargan de una vez. Podría ser lento con historial grande.
- **El estado `listo` se muestra como "En camino"** — es una traducción visual para el cliente. En la BD sigue siendo `listo`.
- **No hay fecha de entrega estimada** — solo muestra la fecha en que se hizo el pedido.
- **Los pedidos creados desde el catálogo** con tipo "domicilio" aparecen aquí automáticamente — no hay que hacer nada especial.
