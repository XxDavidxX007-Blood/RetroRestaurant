# 👨‍💼 Panel de Domicilios — Admin/Empleado

## ¿Qué hace?

Muestra todos los pedidos a domicilio con KPIs, filtros por estado y fecha, tabla paginada, y permite crear nuevos domicilios, cambiar su estado y eliminarlos.

---

## Archivos involucrados

```
views/dashboard/admin_domicilios.php   →  vista completa
Controllers/DomicilioController.php    →  lógica: KPIs, filtros, CRUD
models/Domicilio.php                   →  consultas SQL
```

## Las 5 KPI cards

| Card | Qué muestra | Cómo se calcula |
|---|---|---|
| 🛵 Domicilios hoy | Total del día + % vs ayer | `COUNT WHERE fecha=CURDATE() AND tipo LIKE '%domicilio%'` |
| Pendientes | Total acumulado en ese estado | `COUNT WHERE tipo domicilio AND estado='pendiente'` |
| En preparación | Total acumulado | `COUNT WHERE tipo domicilio AND estado='en_preparacion'` |
| Entregados | Total acumulado | `COUNT WHERE tipo domicilio AND estado='entregado'` |
| Cancelados | Total acumulado | `COUNT WHERE tipo domicilio AND estado='cancelado'` |

A diferencia de reservas, los KPIs de estado **no filtran por fecha** — muestran el total histórico de cada estado.

## Filtros

### Tabs de estado
```
Todos | Pendiente | En preparación | Listo | Entregado | Cancelado
```
Cada tab recarga con `?estado=nombre_estado`.

### Filtro de fecha
`<input type="date">` que al cambiar ejecuta:
```js
function aplicarFecha(val) {
    const url = new URL(window.location.href);
    val ? url.searchParams.set('fecha', val) : url.searchParams.delete('fecha');
    url.searchParams.set('pagina', 1);
    window.location.href = url.toString();
}
```

## Los 3 modales

### Modal Crear
Campos: Cliente (opcional), Mesero (requerido), Fecha del pedido, Estado inicial.

**Particularidad del mesero:** si no hay meseros registrados, el select se reemplaza por un aviso amarillo y el botón "Guardar" se deshabilita:

```php
<?php if (empty($meseros)): ?>
<div class="bg-yellow-50 border border-yellow-200 ...">
    No hay empleados registrados. Registra un usuario con rol Empleado primero.
</div>
<input type="hidden" name="id_mesero" value="0">
<?php else: ?>
<select name="id_mesero" required>...</select>
<?php endif; ?>

<button type="submit" <?= empty($meseros) ? 'disabled' : '' ?>>Guardar</button>
```

**En el modelo**, al crear busca el `id_tipo_pedido` de domicilio automáticamente:
```php
$tp = $db->query("SELECT id_tipo_pedido FROM tipo_pedido WHERE nombre_tipo LIKE '%domicilio%' LIMIT 1")->fetchColumn();
if (!$tp) throw new Exception("No existe tipo de pedido 'domicilio'");
```

No hay campo de productos en este modal — el domicilio se crea como un pedido vacío (sin `detalle_pedido`). Los productos se agregarían por otro flujo.

### Modal Cambiar Estado
Pre-selecciona el estado actual por ID numérico:

```js
function abrirEstado(id, estadoActual) {
    document.getElementById('est_id').value = id;
    const sel = document.getElementById('est_select');
    for (let i = 0; i < sel.options.length; i++) {
        if (sel.options[i].value == estadoActual) { // compara por value (id numérico)
            sel.selectedIndex = i; break;
        }
    }
    document.getElementById('modalEstado').classList.remove('hidden');
}
```

Envía POST con `accion=cambiar_estado`, `id_pedido` e `id_estado_pedido`.

### Modal Eliminar
Muestra el número de pedido (`#ORD-00042`) en el mensaje de confirmación:

```js
function abrirEliminar(id, num) {
    document.getElementById('del_id').value = id;
    document.getElementById('del_num').textContent = num; // "#ORD-00042"
    document.getElementById('modalEliminar').classList.remove('hidden');
}
```

La eliminación borra en cascada con transacción:
```sql
BEGIN TRANSACTION
  DELETE FROM detalle_pedido WHERE id_pedido = :id
  DELETE FROM factura         WHERE id_pedido = :id
  DELETE FROM pedido          WHERE id_pedido = :id
COMMIT
```

## Flujo CRUD en el controlador

```php
switch ($accion) {
    case 'crear':         → INSERT pedido (tipo=domicilio, sin detalle)
    case 'cambiar_estado':→ UPDATE pedido SET id_estado_pedido=:e WHERE id_pedido=:id
    case 'eliminar':      → DELETE detalle + factura + pedido (transacción)
}
// Todos redirigen con ?success=X o ?error=mensaje
```

## Cosas a tener en cuenta

- **No hay campo de productos al crear** — el domicilio se crea como pedido vacío. Si se necesita agregar productos, habría que hacerlo desde el módulo de pedidos.
- **El botón "Guardar" se deshabilita** si no hay meseros — protección visual, pero no hay validación server-side que lo bloquee si alguien envía el formulario manualmente.
- **Los KPIs de estado son históricos** — no filtran por fecha, a diferencia de reservas que solo cuenta hoy.
- **La eliminación borra todo** — pedido, detalle y factura. No hay papelera ni forma de recuperar.
