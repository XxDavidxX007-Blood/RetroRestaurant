# 🗄️ Reservas — Modelo y Consultas SQL

## ¿Qué es?

`models/Reserva.php` centraliza todas las consultas SQL del módulo de reservas para el panel admin. El panel del cliente hace algunas queries directamente en la vista.

---

## Métodos del modelo

### KPIs

```sql
-- getReservasHoy():
SELECT COUNT(*) FROM reserva WHERE DATE(fecha_reserva) = CURDATE()

-- getReservasAyer():
SELECT COUNT(*) FROM reserva WHERE DATE(fecha_reserva) = CURDATE() - INTERVAL 1 DAY

-- getReservasManana():
SELECT COUNT(*) FROM reserva WHERE DATE(fecha_reserva) = CURDATE() + INTERVAL 1 DAY

-- getConteoByEstado($nombre_estado):
SELECT COUNT(*) FROM reserva r
JOIN estado_reserva er ON r.id_estado_reserva = er.id_estado_reserva
WHERE er.nombre_estado = :estado AND DATE(r.fecha_reserva) = CURDATE()
-- Solo cuenta reservas de HOY, no históricas
```

---

### `getAll($filtro_estado, $filtro_fecha, $pagina, $por_pagina)`

Construye el WHERE dinámicamente igual que en pedidos:

```sql
SELECT
    r.id_reserva,
    r.hora_reserva,
    r.fecha_reserva,
    r.numero_personas,
    er.nombre_estado        AS estado,
    er.id_estado_reserva,
    COALESCE(u.nombre, 'Sin cliente')  AS nombre_cliente,
    COALESCE(u.apellidos, '')          AS apellidos_cliente,
    COALESCE(u.telefono, '—')          AS telefono_cliente,
    m.numero_mesa,
    m.capacidad             AS capacidad_mesa,
    m.estado                AS estado_mesa
FROM reserva r
JOIN estado_reserva er ON r.id_estado_reserva = er.id_estado_reserva
LEFT JOIN mesa m       ON r.id_mesa           = m.id_mesa
LEFT JOIN cliente c    ON r.id_cliente        = c.id_cliente
LEFT JOIN usuario u    ON c.id_usuario        = u.id_usuario
[WHERE ...]
ORDER BY r.fecha_reserva ASC, r.hora_reserva ASC
LIMIT :limit OFFSET :offset
```

- `COALESCE` — si no hay cliente asignado, muestra "Sin cliente" y "—"
- `LEFT JOIN mesa` — una reserva podría no tener mesa asignada (aunque el form lo requiere)
- Orden `ASC` — las más próximas primero (diferente a pedidos que usa `DESC`)

---

### `crear($datos)`

```sql
INSERT INTO reserva (id_cliente, id_mesa, fecha_reserva, hora_reserva, numero_personas, id_estado_reserva)
VALUES (:id_cliente, :id_mesa, :fecha_reserva, :hora_reserva, :numero_personas, :id_estado_reserva)
```

`id_cliente` puede ser `null` — el admin puede crear reservas sin cliente asignado.

---

### `actualizar($id, $datos)`

```sql
UPDATE reserva SET
    id_mesa           = :id_mesa,
    fecha_reserva     = :fecha_reserva,
    hora_reserva      = :hora_reserva,
    numero_personas   = :numero_personas,
    id_estado_reserva = :id_estado_reserva
WHERE id_reserva = :id
```

No actualiza `id_cliente` — el cliente de una reserva no se puede cambiar una vez creada.

---

### `eliminar($id)`

```sql
DELETE FROM reserva WHERE id_reserva = :id
```

Simple DELETE sin verificación de estado — la validación de negocio la hace el controlador o la vista.

---

### Catálogos

```sql
-- getEstados():
SELECT id_estado_reserva, nombre_estado FROM estado_reserva ORDER BY id_estado_reserva

-- getMesas():
SELECT id_mesa, numero_mesa, capacidad, estado FROM mesa ORDER BY numero_mesa

-- getClientes():
SELECT c.id_cliente, u.nombre, u.apellidos, u.telefono
FROM cliente c JOIN usuario u ON c.id_usuario = u.id_usuario
ORDER BY u.nombre
```

Se usan para llenar los selects de los modales.

---

## Relación entre tablas

```
reserva
  ├── id_estado_reserva → estado_reserva (pendiente, confirmada, cancelada, completada, no asistio)
  ├── id_mesa           → mesa (numero_mesa, capacidad, estado)
  └── id_cliente        → cliente → usuario (nombre, apellidos, teléfono)
```

---

## Diferencia con el panel del cliente

El panel del cliente (`cliente_reservas.php`) hace sus propias queries directamente, sin pasar por el modelo para los listados y KPIs:

```php
// Ejemplo — KPI "Próximas" en cliente_reservas.php:
$proximasReservas = (int)$db->query("
    SELECT COUNT(*) FROM reserva r
    JOIN estado_reserva er ON r.id_estado_reserva = er.id_estado_reserva
    WHERE r.id_cliente = $id_cliente
      AND r.fecha_reserva >= CURDATE()
      AND er.nombre_estado NOT IN ('cancelada','completada')
")->fetchColumn();
```

Para crear y editar sí usa el modelo directamente:
```php
$model = new Reserva($db);
$r = $model->crear($datos);
$r = $model->actualizar($id_reserva, $datos);
```

---

## Cosas a tener en cuenta

- **No hay validación de conflictos de mesa** — el modelo no verifica si ya existe una reserva para la misma mesa en la misma fecha y hora. Dos reservas pueden coincidir sin error.
- **`getConteoByEstado` solo cuenta hoy** — si se quisiera un conteo histórico, habría que modificar la query quitando el `AND DATE(r.fecha_reserva) = CURDATE()`.
- **`actualizar` no toca `id_cliente`** — si se necesita reasignar una reserva a otro cliente, habría que agregar ese campo al UPDATE.
