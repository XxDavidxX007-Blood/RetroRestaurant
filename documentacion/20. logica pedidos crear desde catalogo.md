# 🛒 Crear Pedido desde el Catálogo — Cliente

## ¿Qué hace?

El cliente elige un plato del catálogo, configura su pedido en un modal y lo confirma. El sistema crea el pedido, la factura y las notificaciones en una sola transacción.

---

## Archivos involucrados

```
views/dashboard/cliente_catalogo.php   →  grid de platos + modal de confirmación + JS
Controllers/ProcesarCompra.php         →  endpoint AJAX que recibe el JSON del carrito
Controllers/CompraController.php       →  crea todo en la BD (transacción)
```

---

## Paso 1 — El catálogo

PHP consulta los platos con `es_menu = 1 AND disponible = 1` y los pinta en un grid. Cada tarjeta tiene un botón `+` que abre el modal:

```js
// Botón + en cada tarjeta:
onclick="abrirModal(id_producto, nombre, precio, emoji, categoria, desc, imagen)"
```

Los datos del plato viajan como parámetros de la función — no hay petición al servidor para abrir el modal.

---

## Paso 2 — El modal de confirmación

Tiene dos columnas:

**Columna izquierda:**
- Imagen del plato (o emoji si no tiene imagen)
- Nombre, categoría, descripción
- Selector de cantidad (`+` / `−`, mínimo 1)
- Campo de observaciones (opcional)

**Columna derecha:**
- Campo de nombre del cliente (opcional)
- Selector de tipo de pedido (Mesa / Domicilio / Para llevar)
- Si elige Domicilio → aparece el aviso de dirección de entrega
- Resumen del pedido (producto, cantidad, precio unitario, total)
- Botón "Agregar y confirmar pedido"

```js
// Al abrir el modal:
function abrirModal(id, nombre, precio, emoji, categoria, desc, img) {
    productoActual = { id_producto:id, nombre, precio, emoji, img };
    qtyActual = 1;
    tipoActual = 'mesa';
    // ... llena todos los campos del modal
    actualizarTotal(); // precio * cantidad
}

// Al cambiar cantidad:
function cambiarQty(delta) {
    qtyActual = Math.max(1, qtyActual + delta);
    actualizarTotal();
}

// Al cambiar tipo:
function selTipo(t) {
    tipoActual = t;
    // Activa la tarjeta seleccionada visualmente
    // Si es domicilio → muestra el aviso de dirección
}
```

## Paso 3 — Confirmar el pedido (AJAX)

Al hacer clic en "Agregar y confirmar pedido":

```js
async function confirmarCompra() {
    const res = await fetch('../../Controllers/ProcesarCompra.php', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
            carrito: [{
                id_producto: productoActual.id_producto,
                nombre:      productoActual.nombre,
                precio:      productoActual.precio,
                cantidad:    qtyActual,
                observacion: obs
            }],
            tipo: tipoActual,          // 'mesa', 'domicilio', 'para llevar'
            cliente_manual: cli        // nombre opcional
        })
    });
    const data = await res.json(); // { ok: true, id_pedido: 42, total: 25000 }
}
```

El carrito solo tiene un producto — el modal es de un plato a la vez. Si el cliente quiere más platos, cierra el modal y repite el proceso (cada confirmación crea un pedido nuevo).

---

## Paso 4 — ProcesarCompra.php

Es el endpoint AJAX. Valida la sesión, obtiene el `id_cliente` y delega a `CompraController`:

```php
// Valida que sea cliente
if (!in_array($_SESSION['usuario']['id_rol'], [3,'3','cliente'])) {
    echo json_encode(['ok'=>false,'error'=>'No autorizado']); exit;
}

// Lee el JSON del body
$data    = json_decode(file_get_contents('php://input'), true);
$carrito = $data['carrito'] ?? [];
$tipo    = $data['tipo']    ?? 'mesa';

// Obtiene id_cliente desde la sesión
$stmt->execute([':id' => $_SESSION['usuario']['id_usuario']]);
$row = $stmt->fetch();

// Delega
$ctrl   = new CompraController();
$result = $ctrl->procesarCompra($row['id_cliente'], $carrito, $tipo);
echo json_encode($result);
```

---

## Paso 5 — CompraController::procesarCompra()

Toda la creación del pedido ocurre en una **transacción**. Si cualquier paso falla, se deshace todo:

```php
BEGIN TRANSACTION

  // 1. Busca el id del tipo de pedido ('mesa' → id 1, etc.)
  SELECT id_tipo_pedido FROM tipo_pedido WHERE nombre_tipo = :tipo

  // 2. Busca el estado 'pendiente'
  SELECT id_estado_pedido FROM estado_pedido WHERE nombre_estado = 'pendiente'

  // 3. Asigna el primer mesero disponible
  SELECT id_mesero FROM mesero LIMIT 1
  // Si no hay meseros → lanza excepción → ROLLBACK

  // 4. Crea el pedido
  INSERT INTO pedido (id_cliente, id_mesero, id_tipo_pedido, fecha_pedido, id_estado_pedido)
  VALUES (...)

  // 5. Crea un detalle por cada producto del carrito
  INSERT INTO detalle_pedido (id_pedido, id_producto, cantidad, precio_unitario, subtotal)
  // subtotal = precio * cantidad

  // 6. Crea la factura con el total acumulado
  INSERT INTO factura (id_pedido, id_cliente, fecha, metodo_pago, total_factura)
  VALUES (..., 'efectivo', total)

  // 7. Notifica a todos los admins (rol 1)
  INSERT INTO notificacion (...) para cada admin

  // 8. Notifica al cliente que su pago fue confirmado
  INSERT INTO notificacion (...) para el cliente

COMMIT → retorna { ok:true, id_pedido, total }
```

---

## Paso 6 — Modal de éxito

Si `data.ok === true`, se cierra el modal de confirmación y se abre el modal de éxito:

```js
document.getElementById('ok-msg').innerHTML =
    `Tu pedido <strong>#ORD-00042</strong> fue procesado.<br>
     Total a pagar: <strong>$25.000</strong><br>
     ¡Pronto estará listo!`;
document.getElementById('modal-ok').classList.add('show');
```

---

## Cosas a tener en cuenta

- **Un pedido = un producto** — el modal solo agrega un plato por confirmación. No hay carrito acumulado entre platos.
- **El mesero se asigna automáticamente** — siempre es el primero de la tabla `mesero`. Si no hay meseros registrados, el pedido falla.
- **El método de pago siempre es `efectivo`** — está hardcodeado en el INSERT de factura.
- **Las notificaciones se crean dentro de la transacción** — si fallan, el pedido tampoco se guarda.
- **No hay validación de stock** — se puede pedir un plato aunque el inventario esté en cero.
