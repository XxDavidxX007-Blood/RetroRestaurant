# 🗄️ Pedidos — Modelo y Consultas SQL

## ¿Qué es?

`models/Pedido.php` centraliza todas las consultas SQL del módulo de pedidos para el panel admin. El panel del cliente hace sus queries directamente en la vista.

---

## Métodos del modelo

### `getPedidosHoy()` y `getPedidosAyer()`

```sql
-- Hoy:
SELECT COUNT(*) FROM pedido WHERE DATE(fecha_pedido) = CURDATE()

-- Ayer:
SELECT COUNT(*) FROM pedido WHERE DATE(fecha_pedido) = CURDATE() - INTERVAL 1 DAY
```

Se usan para calcular la variación porcentual en el KPI "Pedidos hoy".

---

### `getConteoByEstado($nombre_estado)`

```sql
SELECT COUNT(*) FROM pedido p
JOIN estado_pedido ep ON p.id_estado_pedido = ep.id_estado_pedido
WHERE ep.nombre_estado = :estado
```

Se llama una vez por cada estado para llenar las KPI cards.

---

### `getAll($filtro_estado, $filtro_fecha, $pagina, $por_pagina)`

La consulta principal de la tabla. Construye el WHERE dinámicamente:

```php
$where  = [];
$params = [];

if ($filtro_estado !== 'todos') {
    $where[] = "ep.nombre_estado = :estado";
    $params[':estado'] = $filtro_estado;
}
if ($filtro_fecha) {
    $where[] = "DATE(p.fecha_pedido) = :fecha";
    $params[':fecha'] = $filtro_fecha;
}

$whereSQL = $where ? 'WHERE ' . implode(' AND ', $where) : '';
$offset   = ($pagina - 1) * $por_pagina;
```

```sql
SELECT
    p.id_pedido,
    COALESCE(u.nombre, 'Sin cliente')  AS nombre_cliente,
    COALESCE(u.telefono, '—')          AS telefono_cliente,
    tp.nombre_tipo                     AS tipo,
    ep.nombre_estado                   AS estado,
    IFNULL(f.total_factura, 0)         AS total,
    p.fecha_pedido,
    m.nombre_mesero                    AS mesero
FROM pedido p
JOIN estado_pedido ep  ON p.id_estado_pedido = ep.id_estado_pedido
JOIN tipo_pedido   tp  ON p.id_tipo_pedido   = tp.id_tipo_pedido
LEFT JOIN cliente  c   ON p.id_cliente       = c.id_cliente
LEFT JOIN usuario  u   ON c.id_usuario       = u.id_usuario
LEFT JOIN factura  f   ON f.id_pedido        = p.id_pedido
LEFT JOIN (
    SELECT m2.id_mesero, u2.nombre AS nombre_mesero
    FROM mesero m2 JOIN usuario u2 ON m2.id_usuario = u2.id_usuario
) m ON p.id_mesero = m.id_mesero
[WHERE ...]
ORDER BY p.id_pedido DESC
LIMIT :limit OFFSET :offset
```

- `COALESCE` — si no hay cliente o teléfono, muestra texto por defecto
- `IFNULL` — si no hay factura, el total es 0
- El subquery de mesero evita un JOIN doble con `usuario`
- `LEFT JOIN` en cliente/factura — un pedido puede existir sin factura o sin cliente asignado

### `getTotalCount($filtro_estado, $filtro_fecha)`

Mismos filtros que `getAll()` pero solo cuenta — se usa para calcular el total de páginas:

```sql
SELECT COUNT(*) FROM pedido p
JOIN estado_pedido ep ON p.id_estado_pedido = ep.id_estado_pedido
[WHERE ...]
```

---

### `getById($id_pedido)`

Igual que `getAll()` pero para un solo pedido. Incluye además `ep.id_estado_pedido` (necesario para pre-seleccionar el estado en el modal de cambio).

---

### `getDetalle($id_pedido)`

```sql
SELECT
    dp.cantidad,
    dp.precio_unitario,
    dp.subtotal,
    pr.nombre AS producto
FROM detalle_pedido dp
JOIN producto pr ON dp.id_producto = pr.id_producto
WHERE dp.id_pedido = :id
```

Devuelve los productos del pedido con sus cantidades y subtotales.

---

### `getEstados()`

```sql
SELECT id_estado_pedido, nombre_estado FROM estado_pedido ORDER BY id_estado_pedido
```

Se usa para llenar los tabs de filtro y el select del modal de cambio de estado.

---

### `cambiarEstado($id_pedido, $id_estado_pedido)`

```sql
UPDATE pedido SET id_estado_pedido = :estado WHERE id_pedido = :id
```

Simple UPDATE. No hay validación de transiciones — el admin puede pasar de "cancelado" a "pendiente" si quiere.

---

## Relación entre tablas

```
pedido
  ├── id_estado_pedido → estado_pedido (pendiente, en_preparacion, listo, entregado, cancelado)
  ├── id_tipo_pedido   → tipo_pedido   (mesa, domicilio, para llevar)
  ├── id_cliente       → cliente → usuario (nombre, teléfono)
  ├── id_mesero        → mesero  → usuario (nombre del mesero)
  └── id_pedido        → detalle_pedido (productos del pedido)
                       → factura        (total y método de pago)
                       → notificacion   (alertas generadas)
```

---

## Cosas a tener en cuenta

- **No hay validación de transiciones de estado** — el modelo solo hace el UPDATE. La lógica de negocio (ej. "no se puede pasar de cancelado a listo") no está implementada.
- **El total viene de `factura`**, no se recalcula desde `detalle_pedido` en cada consulta. Si alguien edita un detalle sin actualizar la factura, el total mostrado quedaría desactualizado.
- **El modelo no maneja el panel del cliente** — `cliente_pedidos.php` hace sus propias queries directamente.
