# 👤 Mis Pedidos — Panel del Cliente

## ¿Qué hace?

El cliente ve el historial de todos sus pedidos, puede filtrarlos, ver el detalle, editar los que están pendientes, cancelarlos y eliminar los que ya terminaron.

---

## Archivos involucrados

```
views/dashboard/cliente_pedidos.php        →  vista principal: KPIs, tabla, modales, lógica POST
Controllers/PedidoDetalleCliente.php       →  endpoint AJAX para ver/editar detalles
```

Este archivo no usa `PedidoController` — toda la lógica SQL está directamente en la vista.

---

## Acceso

Solo clientes (rol 3). Si no tiene sesión → redirige a `login.php`.

---

## Las 4 KPI cards

Calculadas con queries directas al cargar la página:

| Card | Qué muestra |
|---|---|
| 🧾 Total pedidos | Todos los pedidos del cliente |
| ⏳ En proceso | Pedidos en estado pendiente, en_preparacion o listo |
| ✅ Entregados | Pedidos con estado entregado |
| 💰 Total gastado | Suma de todas las facturas del cliente |

---

## Filtros

Igual que el panel admin: tabs de estado + filtro de fecha. Ambos recargan la página con parámetros GET. La paginación es de 8 pedidos por página.

## Ver detalle (AJAX)

```js
async function verDetalle(id) {
    // Carga el fragmento HTML desde PedidoDetalleCliente.php?id=X&modo=ver
    const res  = await fetch('../../Controllers/PedidoDetalleCliente.php?id=' + id + '&modo=ver');
    const html = await res.text();
    document.getElementById('detalle-body').innerHTML = html;
    document.getElementById('modalDetalle').classList.add('show');
}
```

`PedidoDetalleCliente.php` con `modo=ver` devuelve:
- Fecha, tipo, estado (con badge de color)
- Tabla de productos con cantidad y subtotal
- Total en barra oscura

## Editar pedido (solo si está pendiente)

```js
async function abrirEditar(id, tipoActual) {
    // 1. Pre-selecciona el tipo de pedido actual
    // 2. Carga los productos editables por AJAX (modo=editar)
    const res  = await fetch('../../Controllers/PedidoDetalleCliente.php?id=' + id + '&modo=editar');
    const html = await res.text();
    document.getElementById('edit-productos').innerHTML = html;
    document.getElementById('modalEditar').classList.add('show');
}
```

`PedidoDetalleCliente.php` con `modo=editar` devuelve una fila por producto con:
- Nombre y precio unitario
- Botones `−` y `+` para cambiar cantidad (mínimo 1)
- Botón 🗑️ para quitar el producto (AJAX)

### Cambiar cantidad en el modal

```js
function cambiarCantEdit(btn, delta) {
    const input = btn.closest('.prod-edit-row').querySelector('input[type="number"]');
    let v = Math.max(1, parseInt(input.value) + delta);
    input.value = v;
    actualizarSub(input); // recalcula el subtotal mostrado en pantalla
}
```

El subtotal se actualiza visualmente en tiempo real. El valor real se guarda al enviar el formulario.

### Quitar un producto del pedido (AJAX)

```js
async function eliminarDetalle(btn) {
    const fd = new FormData();
    fd.append('accion',     'eliminar_detalle');
    fd.append('id_pedido',  idPedido);
    fd.append('id_detalle', idDetalle);

    await fetch('cliente_pedidos.php', { method:'POST', body:fd });
    // Recarga los productos en el modal
}
```

**Regla:** no se puede quitar el último producto. Si solo queda uno, el sistema devuelve error y sugiere cancelar el pedido.

### Guardar cambios del pedido

El formulario envía POST con `accion=editar_pedido`:

```php
// cliente_pedidos.php — POST accion=editar_pedido
// 1. Verifica que el pedido sea del cliente y esté pendiente
// 2. Actualiza el tipo de pedido si cambió
// 3. Por cada detalle: recalcula subtotal = precio_unitario * nueva_cantidad
// 4. Recalcula el total en la factura:
$nuevoTotal = SUM(subtotal) FROM detalle_pedido WHERE id_pedido = X
UPDATE factura SET total_factura = :nuevoTotal WHERE id_pedido = X
```

## Eliminar pedido (solo si está cancelado o entregado)

```php
// Verifica que sea del cliente y esté en ('cancelado','entregado')
// Borra en orden:
DELETE FROM detalle_pedido WHERE id_pedido = X
DELETE FROM factura         WHERE id_pedido = X
DELETE FROM pedido          WHERE id_pedido = X AND id_cliente = X
```

El orden importa por las foreign keys.

## Seguridad — verificación doble

Todas las acciones verifican que el pedido pertenezca al cliente antes de ejecutar:

```php
$check = $db->prepare("
    SELECT p.id_pedido FROM pedido p
    JOIN estado_pedido ep ON p.id_estado_pedido = ep.id_estado_pedido
    WHERE p.id_pedido = :id AND p.id_cliente = :c AND ep.nombre_estado = 'pendiente'
");
$check->execute([':id'=>$id_pedido, ':c'=>$id_cliente]);
if ($check->fetch()) { /* ejecutar */ }
```

Si alguien manipula el `id_pedido` en el formulario para intentar editar el pedido de otro cliente, la verificación lo bloquea.

---

## Cosas a tener en cuenta

- **No usa PedidoController** — toda la lógica SQL está directamente en la vista. Funciona pero mezcla responsabilidades.
- **El modal de edición carga los productos por AJAX** — si el servidor tarda, el usuario ve un spinner.
- **El subtotal se recalcula en el servidor** al guardar — el JS solo actualiza la vista, el valor real lo calcula PHP.
- **Eliminar un pedido es permanente** — borra el pedido, sus detalles y su factura. No hay papelera.
- **Solo se puede editar si está pendiente** — en cuanto el admin cambia el estado a "en_preparacion", el cliente ya no puede modificarlo.
