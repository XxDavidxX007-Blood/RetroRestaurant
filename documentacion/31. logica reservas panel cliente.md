# 👤 Mis Reservas — Panel del Cliente

## ¿Qué hace?

El cliente ve solo sus propias reservas, puede crear nuevas, editar las activas (sin cambiar el estado), cancelarlas y eliminar las que ya terminaron.

---

## Archivos involucrados

```
views/dashboard/cliente_reservas.php   →  vista + toda la lógica POST directamente
models/Reserva.php                     →  usado directamente para crear y editar
```

No usa `ReservaController` para las acciones — instancia `Reserva` directamente.

---

## Las 4 KPI cards

| Card | Qué muestra |
|---|---|
| 📅 Total reservas | Todas las reservas del cliente (históricas) |
| ⏰ Próximas | Reservas desde hoy en adelante que no están canceladas ni completadas |
| ✅ Confirmadas | Reservas con estado "confirmada" |
| ❌ Canceladas | Reservas con estado "cancelada" |

## Las 4 acciones disponibles

### 1. Crear reserva
El cliente abre el modal, elige mesa, personas, fecha y hora. **No puede elegir el estado** — siempre se crea como `pendiente` (id hardcodeado como `1`):

```php
$datos = [
    'id_cliente'        => $id_cliente,  // se asigna automáticamente desde la sesión
    'id_mesa'           => (int)$_POST['id_mesa'],
    'fecha_reserva'     => $_POST['fecha_reserva'],
    'hora_reserva'      => $_POST['hora_reserva'],
    'numero_personas'   => (int)$_POST['numero_personas'],
    'id_estado_reserva' => 1,  // siempre pendiente
];
$model = new Reserva($db);
$r = $model->crear($datos);
```

La fecha mínima del `<input type="date">` es hoy (`min="<?= date('Y-m-d') ?>"`) — no se pueden crear reservas en el pasado.

### 2. Editar reserva (solo activas)
Solo disponible si el estado **no es** cancelada, completada o "no asistio". El cliente puede cambiar mesa, personas, fecha y hora — pero **no el estado**:

```php
// Verificación de seguridad:
$check = $db->prepare("
    SELECT r.id_reserva FROM reserva r
    JOIN estado_reserva er ON r.id_estado_reserva = er.id_estado_reserva
    WHERE r.id_reserva = :id AND r.id_cliente = :c
      AND er.nombre_estado NOT IN ('cancelada','completada')
");

// El estado se mantiene igual al actual:
$estadoActual = $db->prepare("SELECT id_estado_reserva FROM reserva WHERE id_reserva=:id");
$datos['id_estado_reserva'] = $estadoActual->fetchColumn();
```

### 3. Cancelar reserva (solo activas)
Botón directo en la tabla — no abre modal, solo envía POST:

```php
// accion=cancelar
$idCancelada = $db->query("SELECT id_estado_reserva FROM estado_reserva WHERE nombre_estado='cancelada' LIMIT 1")->fetchColumn();
$db->prepare("UPDATE reserva SET id_estado_reserva=:e WHERE id_reserva=:id AND id_cliente=:c")
   ->execute([':e'=>$idCancelada, ':id'=>$id_reserva, ':c'=>$id_cliente]);
```

El `AND id_cliente=:c` garantiza que el cliente solo cancele sus propias reservas.

### 4. Eliminar reserva (solo canceladas/completadas/no asistio)
Solo disponible en reservas terminadas:

```php
// Verificación:
$check = $db->prepare("
    SELECT r.id_reserva FROM reserva r
    JOIN estado_reserva er ON r.id_estado_reserva = er.id_estado_reserva
    WHERE r.id_reserva = :id AND r.id_cliente = :c
      AND er.nombre_estado IN ('cancelada','completada','no asistio')
");
// Si pasa → DELETE FROM reserva WHERE id_reserva = :id
```

## Qué botones aparecen según el estado

```php
$esActiva     = !in_array($estado, ['cancelada','completada','no asistio']);
$esEliminable = in_array($estado, ['cancelada','completada','no asistio']);

if ($esActiva):
    // Botón lápiz (editar)
    // Botón X (cancelar) — en el formulario de la tabla
elseif ($esEliminable):
    // Botón basura (eliminar)
else:
    // Sin botones
```

## Pre-llenado del modal de edición

```js
function abrirEditar(r) {
    document.getElementById('edit_id').value       = r.id_reserva;
    document.getElementById('edit_personas').value = r.numero_personas;
    document.getElementById('edit_fecha').value    = r.fecha_reserva;
    document.getElementById('edit_hora').value     = r.hora_reserva.substring(0, 5);

    // Mesa: busca por texto "Mesa X (cap. Y)"
    const sm = document.getElementById('edit_mesa');
    for (let i = 0; i < sm.options.length; i++) {
        if (sm.options[i].text.startsWith('Mesa ' + r.numero_mesa + ' ')) {
            sm.selectedIndex = i; break;
        }
    }
    document.getElementById('modalEditar').classList.add('show');
}
```

El modal de edición del cliente **no tiene select de estado** — a diferencia del admin.

## Filtros

Tabs por estado (Todas / pendiente / confirmada / cancelada / completada) + filtro de fecha manual. Ambos recargan la página con parámetros GET. Paginación de 8 por página.

---

## Seguridad — verificación doble

Todas las acciones verifican que la reserva pertenezca al cliente antes de ejecutar. Si alguien manipula el `id_reserva` en el formulario para intentar editar la reserva de otro cliente, la verificación con `AND r.id_cliente = :c` lo bloquea.

---

## Cosas a tener en cuenta

- **El estado siempre es "pendiente" al crear** — el cliente no puede crear una reserva confirmada directamente. Debe esperar que el admin la confirme.
- **El cliente no puede cambiar el estado** — ni al editar. El estado lo maneja exclusivamente el admin.
- **No hay validación de disponibilidad de mesa** — igual que en el panel admin, se puede reservar una mesa ya ocupada.
- **La fecha mínima es hoy** — el `<input type="date">` tiene `min="<?= date('Y-m-d') ?>"` para evitar reservas en el pasado.
- **Los modales usan clases CSS** (`show`/sin `show`) en lugar de `hidden` de Tailwind — diferente al patrón del admin que usa `hidden`.
