# 👥 Controladores de Usuario — UsuarioController y AdminUsuarioController

## ¿Qué son?

Son dos controladores que manejan la creación y edición de usuarios. Cada uno atiende un contexto diferente:

| Controlador | Contexto | Quién lo usa |
|---|---|---|
| `UsuarioController` | Registro público desde la web | Formulario `registre.php` |
| `AdminUsuarioController` | Gestión de usuarios desde el panel admin | Vista `admin.php` (panel de usuarios) |

---

## UsuarioController

### Archivo
```
Controllers/UsuarioController.php
```

### ¿Qué hace?
Procesa el formulario de registro público. Valida los datos, verifica que el email no exista y crea el usuario en la BD.

### Flujo
```
POST desde registre.php
        │
        ├── Verifica que todos los campos estén llenos
        ├── Valida formato de email (filter_var)
        ├── Verifica que las contraseñas coincidan
        ├── Verifica que la contraseña tenga mínimo 6 caracteres
        ├── Verifica que el email no esté registrado (Usuario::existeemail)
        ├── Hashea la contraseña con password_hash(PASSWORD_DEFAULT)
        ├── Llama a Usuario::registrar($datos)
        └── Guarda alerta en $_SESSION['alert'] y redirige a registre.php
```

### Validaciones
```php
// 1. Campos vacíos
if (empty($nombre) || empty($apellidos) || empty($email) || ...) → warning

// 2. Formato de email
if (!filter_var($email, FILTER_VALIDATE_EMAIL)) → error

// 3. Contraseñas coinciden
if ($password !== $confirmar_password) → error

// 4. Longitud mínima
if (strlen($password) < 6) → warning

// 5. Email duplicado
if ($usuario->existeemail($email)) → error
```

### El rol por defecto
```php
$id_rol = trim($_POST['id_rol'] ?? '3'); // 3 = cliente por defecto
```

El formulario público siempre registra clientes. El campo `id_rol` viene del form pero tiene `3` como fallback.

### Alertas con `$_SESSION['alert']`
```php
$_SESSION['alert'] = [
    'icon'     => 'success',
    'title'    => 'Registro exitoso',
    'text'     => '¡Bienvenido! Tu cuenta ha sido creada correctamente.',
    'redirect' => 'login.php'  // solo en éxito → redirige al login
];
```

El campo `redirect` solo aparece en el caso de éxito — la vista de registro lo detecta y redirige al login automáticamente.

## AdminUsuarioController

### Archivo
```
Controllers/AdminUsuarioController.php
```

### ¿Qué hace?
Permite al admin crear y editar usuarios desde el panel. Tiene dos acciones: `crear` y `editar`.

### Acceso
Verifica sesión de admin (rol 1) **antes de instanciar la clase** — si no es admin, redirige al login inmediatamente:

```php
if (!isset($_SESSION['usuario']) || !in_array($_SESSION['usuario']['id_rol'], [1,'1','administrador'])) {
    header("Location: .../login.php"); exit;
}
```

### Acción `crear`
```
POST desde admin.php (modal de nuevo usuario)
        │
        ├── Verifica campos obligatorios (nombre, apellidos, email, password, id_rol)
        ├── Verifica email duplicado
        ├── Hashea la contraseña
        ├── Llama a Usuario::registrar($datos)
        └── Guarda alerta en $_SESSION['alert'] y redirige a admin.php
```

### Acción `editar`
```
POST desde admin.php (modal de editar usuario)
        │
        ├── Verifica que id_usuario esté presente
        ├── Arma $datos con nombre, apellidos, id_rol
        ├── Si viene password → la hashea y la incluye en $datos
        │   Si no viene → no toca la contraseña actual
        ├── Llama a Usuario::actualizar($id_usuario, $datos)
        └── Guarda alerta en $_SESSION['alert'] y redirige a admin.php
```

**La contraseña es opcional al editar** — si el admin deja el campo vacío, la contraseña del usuario no cambia.

### Cómo se activa cada acción

El archivo se llama directamente con un parámetro GET:
```
AdminUsuarioController.php?accion=crear
AdminUsuarioController.php?accion=editar
```

```php
$accion = $_GET['accion'] ?? '';
switch ($accion) {
    case 'crear':  $controller->crear();  break;
    case 'editar': $controller->editar(); break;
    default: header("Location: .../admin.php"); exit;
}
```

## El modelo compartido — `Usuario`

Ambos controladores usan `models/usuario.php`. Los métodos relevantes:

```php
// Verifica si el email ya existe
Usuario::existeemail($email) → bool

// Crea usuario + registro en tabla cliente/mesero según el rol
Usuario::registrar($datos) → true | string (mensaje de error)

// Actualiza nombre, apellidos, rol y opcionalmente contraseña
Usuario::actualizar($id_usuario, $datos) → true | string
```

---

## Diferencias clave entre los dos controladores

| Aspecto | UsuarioController | AdminUsuarioController |
|---|---|---|
| Rol que puede usarlo | Cualquiera (público) | Solo admin (rol 1) |
| Acciones | Solo `registrar` | `crear` y `editar` |
| Rol asignado | Siempre cliente (3) por defecto | El admin elige el rol |
| Validación de contraseña | Sí (longitud, coincidencia) | No (solo hashea si viene) |
| Redirect en éxito | A `registre.php` con alerta | A `admin.php` con alerta |
| Redirect en éxito de registro | Incluye `redirect: 'login.php'` | No |

---

## Cosas a tener en cuenta

- **`UsuarioController` no verifica sesión** — es público, cualquiera puede llamarlo.
- **`AdminUsuarioController` verifica sesión fuera de la clase** — la verificación ocurre antes de que se instancie el controlador, en el scope global del archivo.
- **Ambos usan `$_SESSION['alert']`** para comunicar el resultado a la vista — el mismo sistema de alertas que usa `AuthController`.
- **`UsuarioController` no tiene acción de editar** — la edición del propio perfil la maneja `PerfilController`.
