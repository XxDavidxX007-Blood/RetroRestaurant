# 🍽️ Catálogo del Cliente

## ¿Qué es?

Es la página donde el cliente (y el empleado) ven los platos disponibles del menú y hacen pedidos. Tiene un grid de tarjetas, filtros en tiempo real, y un modal de confirmación de dos columnas para configurar y confirmar el pedido.

---

## Archivo

```
views/dashboard/cliente_catalogo.php
```

---

## Acceso

Roles 3 (cliente) y 2 (empleado). Cualquier otro → redirige a `login.php`.

---

## Lo que hace al cargar

Dos queries directas a la BD — sin controlador ni modelo:

```php
$db = (new database())->conectar();

// Detecta si existe la columna es_menu (compatibilidad con producción)
$cols = $db->query("SHOW COLUMNS FROM producto")->fetchAll(PDO::FETCH_COLUMN);
$tieneEsMenu = in_array('es_menu', $cols);
$whereMenu   = $tieneEsMenu
    ? "WHERE p.es_menu = 1 AND p.disponible = 1"
    : "WHERE p.disponible = 1";

// 1. Platos del menú disponibles
SELECT p.id_producto, p.nombre, p.descripcion, p.precio, p.imagen,
       cp.nombre_categoria AS categoria
FROM producto p
JOIN categoria_producto cp ON p.id_categoria = cp.id_categoria
{$whereMenu}
ORDER BY cp.nombre_categoria, p.nombre

// 2. Categorías que tienen al menos un plato disponible
SELECT DISTINCT cp.nombre_categoria
FROM categoria_producto cp
JOIN producto p ON p.id_categoria = cp.id_categoria
WHERE p.es_menu = 1 AND p.disponible = 1
ORDER BY cp.nombre_categoria
```

El `SHOW COLUMNS` es una verificación de compatibilidad — en producción la columna `es_menu` puede no existir, y en ese caso filtra solo por `disponible = 1`.

## Las 3 secciones de la vista

### 1. Header con filtros

```
[Buscar plato...]  [Select de categoría]
```

Ambos filtran en tiempo real con JS — sin recargar la página:

```js
function filtrar() {
    const t = document.getElementById('buscar').value.toLowerCase();
    const c = document.getElementById('filtro').value;

    document.querySelectorAll('.item').forEach(el => {
        const ok = el.dataset.nombre.includes(t)
                && (c === '' || el.dataset.categoria === c);
        el.style.display = ok ? '' : 'none';
    });
    // Si no hay resultados → muestra el div #sin
}
```

Los datos de filtrado están en atributos `data-*` de cada tarjeta:
```php
<div class="item"
     data-nombre="<?= strtolower($item['nombre']) ?>"
     data-categoria="<?= $item['categoria'] ?>">
```

### 2. Grid de tarjetas

Grid responsivo: 2 columnas en móvil, hasta 5 en pantallas grandes.

Cada tarjeta tiene:
- **Imagen** — si el plato tiene imagen, se muestra como `background-image`. Si no, muestra un emoji rotativo del array `$emojis`
- **Badge de categoría** — pill rojo con el nombre
- **Nombre** — truncado con `truncate` si es largo
- **Descripción** — máximo 2 líneas (`line-clamp-2`)
- **Precio** — en grande
- **Botón `+`** — abre el modal de confirmación

```php
// Emojis de respaldo cuando no hay imagen:
$emojis = ['🍔','🍕','🥩','🍗','🥗','🍜','🥤','🍰','🍟','🥪','🌮','🍣','🥘','🍱','🧆'];
$emoji  = $emojis[$i % count($emojis)]; // rota cíclicamente
```

Animación de entrada escalonada:
```php
style="animation-delay:<?= $i * 0.04 ?>s"
// Cada tarjeta aparece 40ms después de la anterior
```

### 3. Modal de confirmación (dos columnas)

Se abre al hacer clic en el `+` de cualquier tarjeta:

```js
function abrirModal(id, nombre, precio, emoji, categoria, desc, img) {
    productoActual = { id_producto:id, nombre, precio, emoji, img };
    qtyActual  = 1;
    tipoActual = 'mesa';
    // Llena todos los campos del modal
    actualizarTotal();
    document.getElementById('modal-confirm').classList.add('show');
}
```

**Columna izquierda:**
- Imagen del plato (o emoji si no tiene)
- Nombre, categoría, descripción
- Selector de cantidad (`+` / `−`, mínimo 1)
- Campo de observaciones (opcional, ej: "sin azúcar")

**Columna derecha:**
- Campo de nombre del cliente (opcional)
- Selector de tipo de pedido (3 tarjetas visuales):
  - 🪑 **Mesa** — para consumir en el restaurante
  - 🛵 **Domicilio** — enviado a la dirección del cliente
  - 🛍️ **Llevar** — el cliente recoge el pedido
- Si elige Domicilio → aparece un aviso de dirección de entrega
- Tabla resumen: producto, cantidad, precio unitario
- Total en grande
- Botón "Agregar y confirmar pedido"
- Botón "Agregar más productos" (cierra el modal sin confirmar)

## Confirmar el pedido — AJAX

Al hacer clic en "Agregar y confirmar pedido":

```js
async function confirmarCompra() {
    const btn = document.getElementById('btn-confirmar');
    btn.disabled = true;
    btn.innerHTML = '<i class="fas fa-spinner fa-spin"></i> Procesando...';

    const res = await fetch('../../Controllers/ProcesarCompra.php', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
            carrito: [{
                id_producto: productoActual.id_producto,
                nombre:      productoActual.nombre,
                precio:      productoActual.precio,
                cantidad:    qtyActual,
                observacion: document.getElementById('m-observacion').value
            }],
            tipo:           tipoActual,       // 'mesa', 'domicilio', 'para llevar'
            cliente_manual: document.getElementById('m-cliente').value
        })
    });

    const data = await res.json(); // { ok: true, id_pedido: 42, total: 25000 }

    if (data.ok) {
        cerrarModal();
        // Muestra modal de éxito con número de pedido y total
        document.getElementById('modal-ok').classList.add('show');
    } else {
        alert('Error: ' + data.error);
    }
}
```

El botón se deshabilita mientras procesa para evitar doble envío.

## Flujo completo

```
Cliente entra al catálogo
        │
        ├── PHP consulta platos (es_menu=1 AND disponible=1)
        ├── PHP consulta categorías disponibles
        └── Renderiza el grid
                │
                ├── Cliente filtra (JS, sin recarga)
                │
                └── Cliente hace clic en + de un plato
                        │
                        └── abrirModal() → llena el modal con datos del plato
                                │
                                ├── Elige cantidad, tipo, observaciones
                                └── Clic "Agregar y confirmar pedido"
                                        │
                                        └── fetch POST → ProcesarCompra.php
                                                │
                                                └── CompraController::procesarCompra()
                                                        │
                                                        ├── INSERT pedido
                                                        ├── INSERT detalle_pedido
                                                        ├── INSERT factura
                                                        └── INSERT notificaciones
                                                                │
                                                                └── { ok:true, id_pedido, total }
                                                                        │
                                                                        └── Modal de éxito ✅
```

## Cosas a tener en cuenta

- **Un pedido = un producto** — el modal confirma un plato a la vez. Para pedir varios platos distintos hay que repetir el proceso (cada confirmación crea un pedido nuevo).
- **Los filtros son del lado del cliente** — todos los platos ya están en el HTML al cargar. El filtro solo muestra/oculta con JS, no hace peticiones al servidor.
- **El `SHOW COLUMNS`** se ejecuta en cada carga de página — es una verificación de compatibilidad que podría eliminarse una vez que la columna `es_menu` esté confirmada en producción.
- **El botón `+` se deshabilita** mientras procesa el pedido — evita que el cliente haga clic dos veces y cree pedidos duplicados.
- **El campo "nombre del cliente"** es opcional y no se guarda en ningún campo de la BD — es solo informativo para el empleado que atiende.
- **Las observaciones** tampoco se guardan en la BD actualmente — se envían al servidor pero `CompraController` no las persiste en ninguna columna.
